# CoffeeStrap 0.8.6 experience profiles and safe persistence — October 22, 2026

The launcher already owned named JSON flag snapshots in SavedFlagProfiles and ProfilePlaceIds assignments. This pass continues that storage/selection path rather than adding a second profile manager. Manage experience profiles in Game Tweaks opens the existing dialog in a focused Save/Assign mode. Assigned snapshots replace their other flag values on the next direct launcher preparation. Existing selected-global effects/texture/voxel-lighting authority and an explicit renderer preference remain enforced through one shared CuratedFlagRegistry operation. Unassigning or launching another place returns to the saved global source; absent global source now writes supported defaults instead of retaining an earlier experience's mesh values. Teleporting within an already-running player does not run this preparation again. No live flag/XML reload or FPS gain is claimed.

The new shared FlagProfileFiles path rejects rooted/separated/reserved/linked profile names, caps reads at 1 MiB from one opened stream length, observes cancellation, caps parsed dictionaries at 4096 entries/depth 16 and filters before any destination write. Assignment maps are bounded to 256 profiles/1024 IDs per profile, so a launch checks at most 262144 IDs. The UI enumerates at most 257 file names and displays 256, plus at most 256 assigned names absent from that list. Unsupported input remains in its unchanged original snapshot; it is not copied to launch output or re-archived on every launch. Applied/skipped results enter the existing local file-mod report. Final manifest metadata reflects the filtered output.

Microsoft's DDS layout specifies the 128-byte legacy header, mip order, flags and block-size calculation: https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-header ; https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-file-layout-for-textures ; https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dx-graphics-dds-pguide . The reducer supports two-dimensional DXT1/3/5 and tightly packed 32-bit RGB(A), preserves the original pixel-format structure and copies the selected mip payload byte-for-byte. Preparation occurs after priority selection and default-indoor aliasing. A selected installed/generated source wins; otherwise the original backup is preferred. A previously modified target without its preserved original is never used as a new source. This prevents cumulative shrinking and keeps mod disable/restore semantics. Content-addressed prepared files are atomic and reuse unchanged data. Existing cache pruning remains active. Each file is limited to 64 MiB/16 megapixels/8192 per dimension, at most 14 mip iterations, and two streaming passes for a new output; cached calls still hash the source. There are no game frame/tick callbacks, background polling or GPU/OS mutations. The worst case is bounded by 51 selected source files; large replacements can add launch I/O, so no startup-speed claim is made.

## Historical 0.8.0 scheduling, visual presets and live FPS research — October 22, 2026

Windows process scheduling is exposed through public metadata APIs. CPU priority uses Get/SetPriorityClass; WDDM GPU process priority uses D3DKMTGet/SetProcessSchedulingPriorityClass, with Above Normal enum value 3. The handle requests query/set-information rights only (0x1600), without virtual-memory read/write/operation rights. Microsoft definitions: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmthk/nf-d3dkmthk-d3dkmtsetprocessschedulingpriorityclass and https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmthk/ne-d3dkmthk-_d3dkmt_schedulingpriorityclass . SetProcessInformation(ProcessPowerThrottling) controls execution-speed EcoQoS and whether a process's own timer-resolution requests are honored. ControlMask selects the requested mechanisms; clearing their StateMask opts out of throttling/ignoring those requests. Clearing ControlMask relinquishes explicit control. Native layout is three DWORDs, version 1. No global timeBeginPeriod request is made. Windows docs: https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation and https://learn.microsoft.com/en-us/windows/win32/procthread/quality-of-service . More active CPU/timer policies can consume more battery. Roblox can independently adjust its own policies.

All four options default off, run once for the CoffeeStrap-launched player, check process identity and retain an owned handle. Independent failures are reported; higher existing CPU/GPU priorities are preserved. Cleanup restores only values still matching the request and merges only owned power bits. No recurring process enumeration or per-frame work is introduced. This run successfully applied/read back CPU/GPU/power/timer metadata in the isolated preview process and restored its CPU priority.
